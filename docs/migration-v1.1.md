# اعتماد Wasl v1.1

- المرجع الوحيد للتنفيذ: `docs/wasl-spec-v1.1.md`، وهو نسخة المستند المرفق `وصل1.txt`.
- النسخة السابقة محفوظة في Git عبر `pre-spec-integration-20261127` و`archive/pre-spec-main`.
- `public.app_state` والمسارات القديمة تحت `/api/state` لا تُحذف ولا تُعدّل بياناتها في هذه المرحلة؛ وهي مجمدة للتوافق فقط إلى أن يكتمل قطع `/api/v1` والتحقق من ترحيل البيانات.
- الترحيل `017_wasl_v1_1_relational_core.sql` غير تدميري: ينشئ الجداول العلائقية الجديدة، يضيف أعمدة توافقية فقط، ويشدد `search_path` للدالة القديمة.
- لا يُسمح بتشغيل أي ترحيل يضم `DROP`, `TRUNCATE`, `DELETE` أو نقلًا صامتًا لبيانات المرضى دون خطة ترحيل واختبار واستعادة موثقة.

## ترتيب القطع

1. تطبيق الترحيل 017 والتحقق من الجداول والسياسات والدالة `wasl_transition_referral`.
2. بناء Backend `/api/v1` فوق هذه الجداول فقط، مع `version` و`expected_version` و`Idempotency-Key`.
3. ترحيل البيانات القديمة بخطوة مستقلة قابلة لإعادة التشغيل مع تقرير فروقات.
4. تشغيل اختبارات القبول والأمان، ثم إزالة المسارات القديمة بعد نافذة التجميد المعتمدة.
